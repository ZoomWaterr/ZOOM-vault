# 知识库严厉审查报告

> 日期：2026-05-31
> 结论：当前知识库有骨架，但还不是能真正带人刷题变强的学习系统。

## 0. 总判定

这版库最大的问题不是“少”，而是“薄”。

它现在更像：

- 算法目录
- 速查卡
- 模板仓库
- 自动题型索引
- 一些复盘样例

但它还不像：

- 一个老师真的坐在旁边带你拆题
- 一个能把双层 for、变量角色、复杂度、状态转移讲到你脑子清楚的训练库
- 一个能从 hello-algo 的图解和推演里吸收深度，再转成 Python 刷题能力的系统

严厉评分：

| 维度 | 分数 | 判断 |
|---|---:|---|
| 结构完整度 | 7/10 | 目录、链接、分区基本有了 |
| 教学深度 | 4/10 | 大量页面只有概念和口号 |
| 刷题实战性 | 4/10 | 真正从题目到 AC 的闭环太少 |
| 个人风格贴合度 | 5/10 | 学到了一些“本质、口诀”，但没有学透你的手写笔记风格 |
| HelloAlgo 精读度 | 3/10 | 现在更像章前导读，不是精读 |
| 可长期维护性 | 5/10 | 页面太碎，重复太多，导航有噪音 |

一句话：

> 现在这个库能帮你想起“该用什么词”，但还不能稳定帮你把题写出来。

## 2. 原始手写笔记真正值钱的地方

你的三份手写笔记不是“正式”，但里面有几个很重要的学习特征：

### 2.1 你需要一句话钉住本质

比如你写：

> 前缀和就是从头累加

这句话粗，但有效。它不是百科定义，是脑子里能抓住的东西。

知识库现在有些页面虽然更完整，但容易变成：

> 前缀和用于 O(1) 查询区间和

这句话正确，但离初学者的真实理解差一步。

真正应该写成：

> 前缀和就是先把“从开头到每个位置的总和”存起来。以后问一段，就用右边总和减掉左边前面的总和。

### 2.2 你需要小样例和图

你原来写差分时用了“小朋友”“打两个标记”。

这个方向是对的。对你这种阶段来说，差分不能先讲公式：

```python
diff[l] += c
diff[r + 1] -= c
```

应该先讲：

```text
原数组：  1   2   3   4   5
操作：让第 2 到第 4 个数都 +10

笨办法：  1  12  13  14   5

差分想法：
在 L 位置打一个 +10 标记
在 R+1 位置打一个 -10 标记
中间不一个个改，最后统一累加还原
```

### 2.3 你真正卡的是变量和过程，不是名词

你说“双层 for 有点迷”，这句话很关键。

你不是不知道 `for` 是循环，而是卡在：

- 外层变量现在是谁？
- 内层变量现在是谁？
- 每一轮到底比较了谁和谁？
- `cnt` 为什么这里加？
- `ans.append(cnt)` 为什么不能放进内层？
- 双层循环是不是一定很慢？
- `for j in range(i)` 为什么能保证只看左边？

所以知识库不能只给模板，必须有变量追踪表。

## 3. P0 问题：必须先改

### P0-3：模板库不能再放伪代码

这些模板现在不合格：

- `90_模板库/DP入门模板.md`
- `90_模板库/双指针与滑动窗口模板.md`
- `90_模板库/前缀和模板.md`
- `90_模板库/差分模板.md`
- `90_模板库/DFS与BFS模板.md`

模板必须满足：

- 可直接运行
- 有输入样例
- 有输出样例
- 有边界测试
- 有变量轨迹
- 明确适用条件

不能再出现这种占位：

```python
dp[i] = 从前面的状态转移而来
```

这不是模板，是提醒。

### P0-4：题型索引误导性太强

自动索引现在不能放在主路线里。

主要问题：

- `tempCodeRunnerFile` 被收入洛谷索引
- 很多基础模拟被标成“贪心雏形”
- 普通累加被标成“递推 / DP入门”
- 字符串计数被弱化成“字符串 / 模拟”
- 大量备注都是“补：变量含义 + 暴力复杂度 + 优化点”

统一术语：

| 术语 | 必须满足 |
|---|---|
| 模拟 | 按题意一步步算，不需要算法证明 |
| 枚举 | 把可能情况试一遍，范围能接受 |
| 贪心 | 有局部选择，并且要证明选择后不后悔 |
| 递推 | 当前项由前几项推出，但未必有复杂状态 |
| DP | 有状态定义、转移、初值、遍历顺序 |
| 哈希计数 | 用字典/Counter 统计“谁出现几次” |

## 4. P1 问题：第二阶段重构

### P1-1：HelloAlgo 精读名不副实

现在 `07_HelloAlgo精读` 多数页只是章前导读。

例如：

只写“本章必须掌握什么”不叫精读。

### P1-2：数据结构页太像百科

`03_数据结构` 里很多页面只有定义。

数组页应该讲：

- 下标从 0 开始到底意味着什么

- 二维数组怎么读
- `a[i][j]` 是第几行第几列
- 矩阵转置怎么手算
- `[[]] * n` 为什么危险

图页应该讲：

- 边列表怎么变成邻接表
- `visited` 为什么必须有
- BFS 队列每一轮放了什么
- DFS 递归栈每一层是什么

堆页应该讲：

- `heappush` 后数组怎么变
- `heappop` 弹出谁
- 为什么堆适合 TopK

### P1-3：思维断点页拆太碎

## 6. 合格页面标准

以后每一篇核心教学页，都必须过这个检查表：

```text
1. 我能不能用一句话讲清它的本质？
2. 有没有题目信号？
3. 有没有一个 3 到 6 个数据的小样例？
4. 有没有手算过程？
5. 有没有变量角色表？
6. 有没有逐轮变量追踪？
7. 有没有先讲暴力，再讲为什么优化？
8. 有没有可运行 Python 代码？
9. 有没有至少 2 个真实错法？
10. 有没有边界测试？
11. 有没有 3 到 5 道递进练习？
12. 看完后，我下次做题到底会强在哪里？
```

过不了这 12 条，就不能算“知识库核心页”。

## 10. 下一步执行原则

从现在开始，重构这个库要遵守三条铁律：

### 铁律 1：少而深

宁可 40 篇真能教人的深页，也不要 200 篇薄页。

### 铁律 2：先题后模板

每个算法都先从一道具体题出发：

```text
题目怎么读
暴力怎么想
哪里重复了
怎么优化
变量怎么变
代码怎么写
错法怎么错
下次怎么识别
```

模板只能放最后。

### 铁律 3：每页都回答“我下次会强在哪里”

如果一页看完只知道一个名词，那它不合格。

如果一页看完能让你下次少错一个边界、少迷一个变量、少超时一次，那它才是知识库。
