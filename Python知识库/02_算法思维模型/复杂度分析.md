# 复杂度分析

## 一句话抓本质

复杂度不是数学炫技，它只回答一个刷题问题：

> 数据变大以后，这段代码还能不能跑完？

你写出暴力代码后，第一件事不是高兴，而是看数据范围。

## 先建立数量级感觉

竞赛里可以粗略记：

```text
1 秒大概能跑 10^7 到 10^8 次简单操作
Python 保守一点，先按 10^7 估
```

所以：

| 数据规模 n | 大概能接受 |
|---:|---|
| `n <= 20` | `2^n`、回溯、状态压缩有机会 |
| `n <= 100` | `O(n^3)` 可能可以 |
| `n <= 1000` | `O(n^2)` 常见 |
| `n <= 10^5` | `O(n)` 或 `O(n log n)` |
| `n <= 10^6` | 基本只能 `O(n)` |
| `n <= 10^9` | 多半要数学、二分、公式、快速幂 |

这张表不是绝对，但能帮你第一时间判断方向。

## 常见复杂度像什么

| 复杂度 | 感觉 | 常见代码 |
|---|---|---|
| `O(1)` | 直接算 | 公式、下标访问 |
| `O(log n)` | 每次砍一半 | 二分、堆调整 |
| `O(n)` | 扫一遍 | 单层循环、计数 |
| `O(n log n)` | 排序级别 | 排序、分治 |
| `O(n^2)` | 两两比较 | 双层循环 |
| `O(2^n)` | 每个元素选或不选 | 子集、回溯 |
| `O(n!)` | 全排列 | 排列枚举 |

## 单层循环：扫一遍

```python
for i in range(n):
    print(i)
```

如果循环体里是 `O(1)`，整体就是 `O(n)`。

小样例：

```text
n = 5
i = 0 1 2 3 4
一共 5 次
```

## 双层循环：不一定都是 n*n，但常常还是 O(n^2)

完整双层：

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

次数：

```text
n * n = n^2
```

左边枚举：

```python
for i in range(n):
    for j in range(i):
        print(i, j)
```

次数：

```text
i=0 -> 0
i=1 -> 1
i=2 -> 2
中间继续增加
i=n-1 -> n-1

总次数 = 0 + 1 + 中间项 + (n-1)
       = n(n-1)/2
```

虽然少了一半，但复杂度仍然是 `O(n^2)`。

因为复杂度看的是增长速度，不看常数。

## 用 P1428 看复杂度

代码：

```python
for i in range(n):
    cnt = 0
    for j in range(i):
        if nums[j] < nums[i]:
            cnt += 1
    ans.append(cnt)
```

如果 `n = 6`：

```text
i=0 -> 比较 0 次
i=1 -> 比较 1 次
i=2 -> 比较 2 次
i=3 -> 比较 3 次
i=4 -> 比较 4 次
i=5 -> 比较 5 次

总比较 = 15 次
```

如果 `n = 100000`：

```text
比较次数约 = 100000 * 99999 / 2
          约 = 5,000,000,000
```

50 亿次，Python 基本跑不动。

所以这题如果数据范围很大，就不能只靠双层循环，要考虑更强的数据结构。但入门阶段先把双层循环想清楚是必须的。

## 三层循环：非常危险

```python
for i in range(n):
    for j in range(n):
        for k in range(n):
            print(i, j, k)
```

次数是 `n^3`。

```text
n=100   -> 1,000,000 次
n=1000  -> 1,000,000,000 次
```

看到三层循环，立刻问：

```text
能不能少枚举一层？
能不能用前缀和提前存？
能不能用哈希查？
能不能排序后双指针？
```

## `while n //= 2`：每次砍一半

```python
while n > 1:
    n //= 2
```

如果 `n = 64`：

```text
64 -> 32 -> 16 -> 8 -> 4 -> 2 -> 1
```

只跑 6 次。

这就是 `O(log n)`。

看到“每次范围减半”，就想到：

- [[二分查找]]
- 堆
- 分治

## 排序为什么是常见分界线

Python 排序通常是 `O(n log n)`：

```python
nums.sort()
```

`n = 100000` 时，`n log n` 大概一百多万级别，通常可以。

所以很多题的套路是：

```text
先排序 O(n log n)
再线性扫描 O(n)
总复杂度 O(n log n)
```

例如排序后找相邻差、排序后双指针、排序后贪心。

## 暴力到优化：复杂度视角

优化不是玄学，常见就是减少重复计算。

| 暴力重复了什么 | 常见优化 |
|---|---|
| 每次都重新求一段和 | [[前缀和]] |
| 每次都把区间一个个修改 | [[差分]] |
| 每次都线性找某个值 | 哈希表 / 字典 |
| 枚举所有二元组 | 排序 + 双指针 |
| 答案范围很大但有单调性 | 二分答案 |
| 递归重复算同一个状态 | [[动态规划]] / 记忆化 |

## 真实例子：区间和

假设：

```text
n = 100000
q = 100000
每次问 [l, r] 的和
```

暴力：

```python
for _ in range(q):
    l, r = map(int, input().split())
    s = 0
    for i in range(l, r + 1):
        s += nums[i]
    print(s)
```

最坏情况：

```text
每次查 n 个
q 次
总复杂度 O(nq) = 10^10
```

前缀和：

```python
prefix = [0] * (n + 1)
for i in range(n):
    prefix[i + 1] = prefix[i] + nums[i]

for _ in range(q):
    l, r = map(int, input().split())
    print(prefix[r + 1] - prefix[l])
```

复杂度：

```text
预处理 O(n)
每次查询 O(1)
总复杂度 O(n + q)
```

这才叫优化。

## 复杂度判断流程

做题时按这个顺序：

```text
1. 看 n、m、q 的最大值
2. 写出最直观暴力
3. 算暴力复杂度
4. 对照数据范围，看会不会炸
5. 如果会炸，问重复算了什么
6. 用对应模型优化
```

## 常见误区

### 误区 1：双层 for 一定不能用

错。

如果 `n <= 1000`，`O(n^2)` 很可能可以。

如果 `n <= 100000`，`O(n^2)` 基本不行。

关键看数据范围。

### 误区 2：少一半就不是 O(n^2)

```python
for i in range(n):
    for j in range(i):
        print(i, j)
```

次数是 `n(n-1)/2`，仍然是 `O(n^2)`。

### 误区 3：只看循环层数

```python
for i in range(n):
    nums.sort()
```

外面一层，里面排序 `O(n log n)`，总复杂度是 `O(n^2 log n)` 级别，不是 `O(n)`。

### 误区 4：忽略输入规模里的两个变量

```python
for i in range(n):
    for j in range(m):
        print(i, j)
```

复杂度是 `O(nm)`，不是简单写 `O(n^2)`。

## 练习阶梯

1. 判断 `for i in range(n)` 的复杂度。
2. 判断 `for i in range(n): for j in range(i)` 的复杂度，并写出次数公式。
3. `n=10^5` 时，`O(n^2)` 大约多少次？
4. 区间和多次查询为什么暴力会炸？
5. 给一个三层循环，尝试说出能不能用前缀和、哈希、排序减少一层。

## 验收问题

- 复杂度到底在回答什么问题？
- 为什么 `0+1+中间项+(n-1)` 还是 `O(n^2)`？
- `n=10^5` 时应该优先想什么复杂度？
- 什么叫“重复计算”？
- 你能不能从暴力代码指出哪一段重复了？
